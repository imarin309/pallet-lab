# Palette Lab — ゲーム仕様書

> ドキュメント種別：ゲーム仕様（How / Rules）  
> バージョン：v0.1（プロトタイプ仕様）  
> ステータス：未実装・一部詳細は検証待ち  
> 関連文書：[ゲームコンセプト](./palette-lab-concept.md)  
> 開発想定：Phaser + TypeScript / Vite

## 1. 対象範囲

ブラウザで遊べるシングルプレイヤーの調色パズル。初期版では5ステージを用意する。1ステージの想定プレイ時間は約30秒〜2分。バックエンド、アカウント登録、オンラインランキングは実装しない。

プレイヤーが作る体験の意図は[ゲームコンセプト](./palette-lab-concept.md)を参照。本書は**実装・テストで判断できる具体的な振る舞い**を定義する。

## 2. ルール一覧

| 項目 | 仕様 |
| --- | --- |
| 目標 | お題の色を再現し、できるだけ高いスコアを得る |
| 塗料 | 絵の具の基本12色：赤・橙・黄・黄緑・緑・水色・青・紫・茶・黄土色・白・黒 |
| 追加操作 | 塗料をクリック／タップすると1滴追加する |
| 滴数上限 | 1ステージにつき合計8滴 |
| 取り消し | 1ステージにつき1回、直前の1滴を取り消せる |
| 時間制限 | なし |
| 完成操作 | 1滴以上混ぜた状態で任意のタイミングに「完成」を選ぶ |
| 8滴使用時 | 追加操作を無効化。完成操作は引き続き可能 |
| 採点 | 色の近さを0〜100点のスコアで評価 |
| ステージ数 | 5 |
| 再挑戦 | 可能 |
| ステージ解放 | 低得点でも次のステージに進める |

※「完成は1滴以上で可能」は未定義状態での採点を防ぐための初期版の補足ルール。  
※ 塗料は当初「赤・青・黄・白・黒の5種類」だったが、v0.1 実装後に基本12色へ変更した（経緯は[実装判断の記録](./implementation-decisions.md)）。

## 3. プレイの流れと画面遷移

1. **TitleScene**：「スタート」を選ぶ。
2. **GameScene**：お題色を見て、塗料を追加し、現在色を確認する。
3. **GameScene**：取り消し（必要な場合）か、追加継続／完成を選択する。
4. **ResultScene**：得点・ランク・改善ヒントを確認する。
5. **ResultScene**：「もう一度」または「次のステージ」で遷移する。

5ステージ終了後の動線は、最終ステージの結果画面から「もう一度」または「タイトルへ戻る」を選べるものとする。

### プレイヤー操作と条件

| 操作 | 実行条件 | 結果 |
| --- | --- | --- |
| 塗料を1滴追加 | 未完成・合計7滴以下 | 履歴に追加、滴数と混合色を更新 |
| 1滴戻す | 未完成・1滴以上・取り消し権あり | 最後の1滴を削除、使用滴数を1減らし、取り消し権を消費 |
| 完成 | 未完成・1滴以上 | スコア確定、ResultSceneへ |
| 再挑戦 | 結果画面 | 同じお題を初期状態から始める |
| 次のステージ | 結果画面・最終ステージ以外 | 次のお題を初期状態から始める |

取り消しで戻った1滴は使用可能な残り滴数に戻る。ただし、**取り消し権自体は復活しない**。採点後は操作や取り消しを行えない。

## 4. お題・ステージ定義

- 初期版は固定の5ステージ。
- 各ステージは「お題名」「内部の正解レシピ」「混色関数から生成した目標色」を持つ。
- お題の目標色は、**プレイヤーと同じ混色関数で正解レシピを計算**して生成する。正解レシピの合計は8滴以内とする。
- 目標色はプレイ中、色見本として示す。RGB数値と正解レシピは非公開。
- 結果画面でも初期版は正解レシピをそのまま表示しない。
- 初期版のお題は基礎的な色から、白・黒を使う色、くすんだ中間色へ進む構成を想定する。

### ステージ難易度の方針

| 段階 | お題の特徴 | 目的 |
| --- | --- | --- |
| 初級 | 使う種類の少ない混色 | 色同士の混ざり方に慣れる |
| 中級 | 白・黒が関わる色 | 明暗の調整を学ぶ |
| 上級 | くすんだ色や中間色 | 色相・彩度・明度のバランスを考える |

5つの具体的な正解レシピと並び順はプロトタイプで確定する。

## 5. 混色ロジック

### 必須の性質

1. 同じ塗料を同じ滴数・比率で混ぜた場合、同じ色になる（決定論的）。
2. 1滴追加するたびに結果を再計算して表示できる。
3. お題生成とプレイヤー側の調色に**同一の計算関数**を用いる。
4. UI・PhaserのSceneから切り離した純粋関数として実装する。
5. 将来の混色モデル差し替えに対応できる境界を設ける。

### 採用モデル（未決定）

- RGBの単純加重平均は、現実の絵の具の混色とは異なる（例：黄＋青が期待する緑になりにくい）。
- ゲームとしての納得感を優先し、**簡易的な絵の具風の混色モデル**をプロトタイプで比較して決定する。
- 本格的な顔料の物理シミュレーションは初期版の必須要件ではない。

### 概念的なデータ構造

```ts
// 実装例。正式な型・命名は実装時に調整する。
type Pigment =
  | 'red'
  | 'orange'
  | 'yellow'
  | 'yellowGreen'
  | 'green'
  | 'lightBlue'
  | 'blue'
  | 'purple'
  | 'brown'
  | 'yellowOchre'
  | 'white'
  | 'black';
type Recipe = Partial<Record<Pigment, number>>;
type RgbColor = { r: number; g: number; b: number };
```

内部状態には滴を追加した順番を持つ履歴を保存し、直前の1滴を取り消せるようにする。

## 6. 採点・ランク

### スコア

- 完成色と目標色を比較し、0〜100点の整数で表示する。
- 完全一致は100点。
- 色の差が大きいほど低くなる。
- **色差の尺度・スコア変換式は未決定**。RGB距離と、知覚的な色差に近い尺度をプロトタイプで比較する。
- スコアは滴数の少なさではなく、原則として目標色との近さから決める。

### ランク

| スコア | ランク | 表示 |
| --- | --- | --- |
| 90〜100 | MASTER | ★★★ |
| 75〜89 | EXPERT | ★★ |
| 60〜74 | APPRENTICE | ★ |
| 0〜59 | 再挑戦 | 星なし |

低スコアでもステージを進められる。

### フィードバック

得点に加えて短いコメントを1件表示する。例：

- 「目標より少し暗い色になりました」
- 「赤みが強くなりすぎました」
- 「明るさは近いですが、彩度が足りません」

判定可能な色差の種類に合わせて文章を決める。根拠のないアドバイスは出さず、最初は明度など確実に判定できる項目に絞ってよい。

## 7. 記録・報酬の仕様

- 採点ごとにスコア・ランクを表示する。
- 同一ステージで最高得点・最高ランクを更新できる体験を用意する。
- 最高記録をブラウザの再読込後まで保存するか、セッション中のみとするかは**未決定**。
- 「90点以上を6滴以内」などの実績や、完成色のコレクションは将来機能として扱う。

## 8. UI・操作仕様

### ゲーム画面（GameScene）

```text
┌─────────────────────────────┐
│ Palette Lab      STAGE 01   │
│                             │
│  ┌──────────┐ ┌──────────┐  │
│  │ お題の色 │ │ 現在の色 │  │
│  └──────────┘ └──────────┘  │
│                             │
│       パレット / 混色演出    │
│                             │
│   赤   青   黄   白   黒     │
│   ●    ●    ●    ●    ●     │
│                             │
│    使用 5 / 8滴              │
│                             │
│ [1滴戻す]     [完成！]       │
└─────────────────────────────┘
```

- お題の色と現在の色は同じ大きさで並べる。
- 塗料は色の円形ボタンと名称を組み合わせて表示する。
- 滴数・取り消し権の有無を表示する。
- 塗料ボタンはクリックとタッチの両方に対応する。
- タップしやすい操作領域を確保する。
- お題色の数値は表示しない。
- スマートフォンとPCで画面が破綻しないよう表示サイズを調整する。
- 混色が0滴の間は「未調色」と示し、完成ボタンを無効化する。

### 結果画面（ResultScene）

- お題色と完成色を並べる。
- スコアをアニメーションで表示する。
- ランク（星）と簡単な改善ヒントを表示する。
- 「もう一度」と「次のステージ（最終ステージではタイトルへ）」の操作を設ける。

## 9. 演出仕様

初期版は最小限の演出に限定する。

- 塗料を選ぶとパレットに1滴落ちる。
- 混合色は急に切り替えるのではなく、短いトランジションで変化させる。
- 採点時はスコアをアニメーション表示する。
- 演出は色の判別を妨げない長さ・強さとする。

PhaserのTweenなどを利用する。効果音や大量のパーティクルは必須ではない。

## 10. 実装方針

- Phaser + TypeScript + Viteを使用する。
- UI入力・描画・演出はSceneで扱う。
- 混色ロジック、採点ロジック、お題データはSceneから分離する。
- ReactやVueは使わない。
- 初期版は外部画像がなくても成立するようPhaserの図形描画を優先する。
- バックエンドやデータベースなしで静的ファイルとして配信できるようにする。

```text
src/
├── main.ts
├── scenes/
│   ├── TitleScene.ts
│   ├── GameScene.ts
│   └── ResultScene.ts
├── domain/
│   ├── colorMixing.ts       # 混色ロジック
│   ├── scoring.ts           # 色差と得点
│   └── stageDefinitions.ts  # お題と正解レシピ
└── assets/                  # 必要な場合のみ
```

## 11. v0.1の受け入れ条件

- [ ] ブラウザからゲームを開始できる。
- [ ] 12色の塗料をクリック／タップして1滴ずつ追加できる。
- [ ] 追加のたびに混合色が変化する。
- [ ] 8滴使うと、それ以上追加できない。
- [ ] 1ステージにつき一度だけ最後の1滴を戻せる。
- [ ] 1滴以上混ぜれば任意のタイミングで完成できる。
- [ ] 0〜100点の採点と星評価・ヒントを表示できる。
- [ ] 5ステージを遊び、同じステージへ再挑戦できる。
- [ ] すべてのお題は8滴以内で理論上100点に到達できる。
- [ ] 塗料が落ちる簡単なアニメーションを確認できる。
- [ ] PC・スマートフォンで基本操作ができる。
- [ ] TypeScriptの型チェックとビルドが成功する。
- [ ] 混色とスコア計算の主要ケースをテストできる。

### 初期版の対象外

- オンラインランキング
- デイリーチャレンジ
- ログイン／DB
- カラーチャート収集
- ロボットへの自由塗装
- タイムアタック
- 本格的な顔料の物理シミュレーション

## 12. 未決定事項

実装に入る前またはプロトタイプ評価時に決定する。

1. 混色に使う具体的なアルゴリズム。
2. 色差の尺度とスコアへの変換式。
3. お題5ステージの正解レシピと難易度順。
4. 最高得点をセッション内に限るか、ブラウザに保存するか。
5. フィードバック文と判定条件。

## 13. プレイテストの確認項目

- 初見でルールと操作を理解できるか。
- 次に足す色を予想できるか。
- 残り滴数・取り消し権の表示が分かりやすいか。
- 得点と結果コメントに納得感があるか。
- もう1回遊びたくなるか。

検証目的は[ゲームコンセプト](./palette-lab-concept.md#8-面白さに関する仮説)に記載する。実測結果に応じて制限滴数、取り消し回数、得点閾値を見直す。
